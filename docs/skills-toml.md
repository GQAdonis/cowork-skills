# Skills.toml Configuration Guide

`Skills.toml` is a project-level configuration file for managing Claude Code skills, similar to Cargo.toml for Rust projects. The file is stored at `.cowork/Skills.toml` in your project root.

## Workflow

```
┌─────────────────────────────────────────────────────────────────┐
│                     cowork config workflow                       │
└─────────────────────────────────────────────────────────────────┘

1. Install cowork CLI
   $ cargo install --git https://github.com/anthropics/cowork-skills cli

2. Initialize configuration in your project
   $ cd your-project
   $ cowork config init

   Creates: your-project/.cowork/Skills.toml

3. Configure skills (edit .cowork/Skills.toml or use CLI)
   $ cowork config enable rust-core makepad
   $ cowork config add rust-skills ZhangHanDong/rust-skills

4. Install skill dependencies
   $ cowork config install

5. Apply configuration (optional - generates SKILLS.md)
   $ cowork config apply

Directory structure after init:
   your-project/
   ├── .cowork/
   │   ├── Skills.toml      # Skill configuration
   │   └── Skills.lock      # Installed skills lock (auto-generated)
   ├── skills/              # Local project skills (optional)
   └── ...
```

## Quick Start

```bash
# Initialize .cowork/Skills.toml in your project
cowork config init

# View current configuration
cowork config show

# Add a skill dependency
cowork config add rust-skills ZhangHanDong/rust-skills

# Install all dependencies
cowork config install
```

## File Location

The configuration file is stored at:
- **Project config**: `.cowork/Skills.toml` (in project root)
- **Lock file**: `.cowork/Skills.lock` (auto-generated)
- **Global skills**: `~/.claude/skills/` (shared across projects)
- **Local skills**: `./skills/` (project-specific)

## Skills.lock

`Skills.lock` is automatically generated when you run `cowork config install`. It tracks the exact versions and states of installed skills/plugins.

```toml
# This file is auto-generated by cowork. Do not edit manually.

version = 1

[[package]]
name = "rust-skills"
version = "1.2.0"
source = "github"
scope = "project"
type = "plugin"
install_path = "/path/to/project/.claude/rust-skills"
source_path = "ZhangHanDong/rust-skills"
git_sha = "abc123..."
installed_at = "2024-01-25T10:30:00Z"
updated_at = "2024-01-25T10:30:00Z"
enabled = true
skills = ["m01-ownership", "m02-resource", "rust-router"]

[[package]]
name = "dora-dev"
version = "20240125.103000"
source = "dev"
scope = "project"
type = "symlink"
install_path = "/path/to/project/.claude/skills/dora-dev"
source_path = "/local/path/to/dora-skills"
installed_at = "2024-01-25T10:30:00Z"
updated_at = "2024-01-25T10:30:00Z"
enabled = true
```

**Lock file fields:**

| Field | Description |
|-------|-------------|
| `name` | Package name |
| `version` | Version from plugin.json/package.json, or install timestamp |
| `source` | `github`, `local`, or `dev` |
| `scope` | `global` or `project` |
| `type` | `plugin`, `skills`, or `symlink` |
| `install_path` | Where the package is installed |
| `source_path` | Original repo or local path |
| `git_sha` | Git commit SHA (for GitHub sources) |
| `installed_at` | Installation timestamp |
| `updated_at` | Last update timestamp |
| `enabled` | Whether currently enabled |
| `skills` | List of installed skills |

## File Structure

```toml
# Skills.toml - Project skill configuration

[project]
name = "my-project"
description = "Project description"

[skills.global]
enabled = ["memory-filesystem", "best-skill-creator"]
disabled = []

[skills.install]
rust-skills = "ZhangHanDong/rust-skills"

[skills.groups]
enabled = ["rust-core"]
disabled = []

[triggers]
priority = ["dora-router", "rust-router"]

[triggers.overrides]
"async" = "rust-router"
```

## Sections

### [project]

Project metadata.

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Project name (auto-detected from directory) |
| `description` | string | Optional project description |

### [skills.global]

Configure global skills from `~/.claude/skills/`.

| Field | Type | Description |
|-------|------|-------------|
| `enabled` | array | Whitelist - only these skills are loaded |
| `disabled` | array | Blacklist - these skills are excluded |

**Rules:**
- If `enabled` is empty, all global skills are available
- If `enabled` is set, only listed skills are loaded
- `disabled` always excludes skills, even if in `enabled`

### [skills.install]

Declare skill dependencies from GitHub or local paths.

**Simple form:**
```toml
[skills.install]
rust-skills = "ZhangHanDong/rust-skills"
```

**Detailed form:**
```toml
[skills.install]
# From GitHub with specific skills
tokio = { repo = "user/tokio-skills", skills = ["tokio-runtime", "tokio-sync"] }

# From local path
local = { path = "../my-local-skills" }

# Pinned to specific version
pinned = { repo = "user/repo", ref = "v1.0.0" }

# With target agents
multi = { repo = "user/repo", agents = ["claude-code", "cursor"] }
```

**Plugin form (preserves full repository structure):**
```toml
[skills.install]
# Install as plugin - keeps entire repo structure
makepad = { repo = "user/makepad-skills", plugin = true }

# Plugin with version pinning
dora = { repo = "user/dora-skills", plugin = true, ref = "v2.0" }
```

**Install location (global vs local):**
```toml
[skills.install]
# Install to global ~/.claude/skills/ (default)
rust-skills = "ZhangHanDong/rust-skills"

# Install to project .claude/skills/
my-project = { repo = "user/skills", local = true }
my-plugin = { repo = "user/plugin", plugin = true, local = true }
```

**Disabled dependencies (installed but not enabled):**
```toml
[skills.install]
old-lib = { repo = "user/old", enabled = false }
```

| Field | Type | Description |
|-------|------|-------------|
| `repo` | string | GitHub repository (user/repo) |
| `path` | string | Local filesystem path |
| `skills` | array | Specific skills to install (default: all) |
| `ref` | string | Git reference (branch, tag, commit) |
| `agents` | array | Target AI agents |
| `plugin` | bool | Install as plugin (preserves full repo structure) |
| `local` | bool | Install to project instead of global (default: false) |
| `enabled` | bool | Enable/disable this dependency (default: true) |

### [skills.dev]

Development links (symlinks) for testing local skills during development.

```toml
[skills.dev]
# Simple form: links to project .claude/skills/
my-skill = "/path/to/my-skill-project"

# Detailed form:
dora-dev = { path = "/path/to/dora-skills" }
disabled-dev = { path = "/path/to/skills", enabled = false }

# Plugin form: links to .claude/<name>/ instead of .claude/skills/
dora-plugin = { path = "/path/to/dora-skills", plugin = true }
```

| Field | Type | Description |
|-------|------|-------------|
| `path` | string | Local path to link |
| `local` | bool | Link to project (default: true) |
| `enabled` | bool | Enable/disable this link (default: true) |
| `plugin` | bool | Link as plugin to `.claude/<name>/` (default: false) |

**Link locations:**
- `plugin = false` (default): `.claude/skills/<name>` (skill)
- `plugin = true`: `.claude/<name>/` (plugin)

### [skills.groups]

Enable or disable predefined skill groups.

```toml
[skills.groups]
enabled = ["rust-core", "makepad"]
disabled = ["rust-domains"]
```

**Available groups:**

| Group | Skills | Description |
|-------|--------|-------------|
| `rust-core` | 8 | Basic Rust (ownership, concurrency, error handling) |
| `rust-patterns` | 7 | Design patterns (domain modeling, performance) |
| `rust-domains` | 7 | Domain-specific (web, CLI, fintech, embedded) |
| `makepad` | 11 | Makepad UI framework |
| `dora` | 8 | Dora-rs robotics framework |
| `dora-hubs` | 9 | Dora hub integrations |

Use `cowork config groups` to see all groups and their skills.

### [triggers]

Configure trigger conflict resolution.

```toml
[triggers]
# Priority order (first = highest)
priority = ["dora-router", "rust-router", "makepad-router"]

[triggers.overrides]
# Explicit trigger -> skill mappings
"async" = "rust-router"
"widget" = "makepad-router"
"node" = "dora-router"
```

When multiple skills match the same trigger keyword, the skill with higher priority wins. Overrides provide explicit mappings that bypass priority rules.

## CLI Commands

### Initialize

```bash
# Create Skills.toml with auto-detection of installed plugins/skills
cowork config init

# Auto-detection will:
# 1. Scan ~/.claude/ for global plugins and skills
# 2. Scan .claude/ for project plugins and skills
# 3. Show detected packages and ask for confirmation
# 4. Add selected packages to Skills.toml

# Skip auto-detection (empty config)
cowork config init --no-detect

# Overwrite existing config
cowork config init --force
```

**Auto-detection example output:**

```
Detected installed plugins/skills:

  Global ~/.claude/ (plugins):
    [1] rust-skills v1.2.0
    [2] makepad-skills v0.8.0 (symlink)

  Global ~/.claude/skills/ (skills):
    [3] memory-filesystem

  Project .claude/ (plugins):
    [4] dora-dev (symlink)

? Include in Skills.toml? [Y/n/select 1,2,3]: y
```

### View Configuration

```bash
# Show current config
cowork config show

# List available skill groups
cowork config groups
```

### Manage Dependencies

```bash
# Add from GitHub (installs to global)
cowork config add rust-skills ZhangHanDong/rust-skills

# Add to project local instead of global
cowork config add my-skills user/skills --local

# Add with specific skills
cowork config add tokio user/tokio-skills -s tokio-runtime -s tokio-sync

# Add as plugin
cowork config add makepad user/makepad-skills --plugin

# Add plugin to project local
cowork config add dora user/dora-skills --plugin --local

# Add as disabled (installed but not enabled)
cowork config add old-lib user/old --disabled

# Add with git ref
cowork config add pinned user/repo --ref v1.0.0

# Add development link (symlink for testing)
cowork config add dora-dev /path/to/dora-skills --dev

# Remove dependency
cowork config remove rust-skills

# Install all dependencies
cowork config install
```

### Enable/Disable Skills

```bash
# Enable skill groups
cowork config enable rust-core makepad

# Enable individual skills
cowork config enable memory-filesystem

# Disable skills or groups
cowork config disable rust-domains domain-fintech
```

### Trigger Configuration

```bash
# Set priority order
cowork config priority dora-router rust-router makepad-router

# Override specific trigger
cowork config override "async" rust-router
cowork config override "widget" makepad-router
```

### Generate Output

```bash
# Generate SKILLS.md from config
cowork config apply

# Generate to custom path
cowork config apply -o ./docs/SKILLS.md
```

### Generate Dynamic Router

```bash
# Generate cowork-router based on installed plugins
cowork config router

# Generate router with hooks for auto-triggering
cowork config router --hooks
```

The router command:
1. Scans installed plugins for trigger keywords
2. Generates a dynamic `cowork-router` skill at `.claude/skills/cowork-router/`
3. Optionally generates `hooks.json` for auto-triggering based on keywords

## Skill Resolution Order

When Claude Code processes a query:

1. **Check trigger overrides** - Explicit mappings take precedence
2. **Match triggers** - Find skills matching query keywords
3. **Apply priority** - Higher priority skills win conflicts
4. **Filter by enabled/disabled** - Apply whitelist/blacklist rules
5. **Load skill** - Execute the selected skill

## Best Practices

1. **Start minimal** - Enable only the skills you need
2. **Use groups** - Easier than managing individual skills
3. **Set priorities** - Avoid ambiguous trigger matches
4. **Use overrides** - For domain-specific keywords
5. **Pin versions** - Use `ref` for production stability
